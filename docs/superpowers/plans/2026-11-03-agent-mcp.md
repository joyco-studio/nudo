# Agent over web MCP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any MCP client (Claude Code, Cursor, …) read and edit the graph open in nudo through a hosted MCP endpoint, with the agent's work shown live on the canvas (cursor, ghost node, editing tag, work chip, activity panel, Stop, Undo all).

**Architecture:** A Cloudflare Worker (`apps/mcp`) serves MCP over Streamable HTTP at `/mcp` and a WebSocket at `/bridge/<keyHash>`. One Durable Object per key routes each tool call to the browser tab and waits for its answer. The tab is the source of truth: `apps/editor/src/features/agent` runs each request through a serial queue (arrival animation first, then the store action, then the response) and owns task state, Stop and Undo all. A shared package, `packages/agent-protocol`, holds the message and tool schemas both sides validate against.

**Tech Stack:** TypeScript strict, zod 4, `@modelcontextprotocol/sdk`, Cloudflare Workers + Durable Objects (WebSocket Hibernation API), wrangler, `@cloudflare/vitest-pool-workers`, React 19 + zustand/zundo + `@xyflow/react` + motion, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-agent-mcp-design.md`

## Global Constraints

- No `any`. Use `unknown` and narrow with zod. Assertions are allowed only in brand constructors, as in `packages/core/src/types/ids.ts`.
- All code and identifiers are in English. File and directory names are kebab-case.
- Every UI string goes through i18n, in both `apps/editor/src/i18n/messages/en.ts` and `es.ts`. The `hardcoded-strings.test.ts` test has to keep passing.
- Every new control is operable with the keyboard alone: reachable with Tab, activated with Enter/Space, Escape closes overlays and returns focus to the opener, and focus is always visible. Use the `keyboard-accessibility` skill on every UI task.
- Respect `prefers-reduced-motion`: no cursor travel, and the action applies immediately.
- Agent writes go through the existing store actions (`useEditorStore`), so each one is one undo entry, autosaves and recompiles.
- The Worker never logs or stores the raw key. The Durable Object is addressed by `sha256(key)` as lowercase hex.
- The agent label is the MCP `clientInfo.name`, never a hardcoded "Claude Code".
- Commits use Conventional Commits, without a `Co-Authored-By` line.
- Done means all of these pass: `pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm e2e`.

**Plan calls that refine the spec (they keep its intent):**
- **Key in a header, not in the URL.** The MCP key goes in `Authorization: Bearer <key>`, so it never shows up in request-URL logs. The copied command is `claude mcp add --transport http nudo <url>/mcp --header "Authorization: Bearer <key>"`. The browser connects to `/bridge/<sha256(key)>` and sends the raw key in `hello`.
- **Task state lives in the tab, not in the DO.** Stop, Undo all and the busy check are all decided in the tab. The DO only knows the sockets and the MCP sessions (`sessionId → clientName`). If the tab reloads mid-task, the task is cut, as the spec says.

## Review Focus

1. **The tab closes or reloads while a tool call is waiting.** The call has to resolve right away with `not_connected`, not hang until the timeout. Test in Task 2.
2. **The agent writes to a node the user just deleted.** It gets `not_found` with the current node list, and nothing changes. Test in Task 6.
3. **Two tabs are open with the same key.** Only the most recently focused tab executes; the other shows "working in another tab". Tests in Tasks 2 and 4.
4. **The user presses Ctrl+Z on an agent change in the middle of a task.** The agent's next write still applies, and Undo all still returns to the snapshot taken at `start_task`. Test in Task 7.
5. **Malformed input.** Invalid JSON over the socket, args out of schema (NaN position, unknown node type, unknown port), or a message over 1 MB get a typed `invalid` error. No crash, and the socket stays open. Tests in Tasks 1 and 5.

### Task 2: Worker bridge room (Durable Object)

**Files:**
- Create: `apps/mcp/package.json` (private, deps `@nudo-tsl/agent-protocol`, `@modelcontextprotocol/sdk`, `zod`; devDeps `wrangler`, `@cloudflare/vitest-pool-workers`, `@cloudflare/workers-types`; scripts `dev: wrangler dev`, `deploy: wrangler deploy`, `test`, `typecheck`, `lint`)
- Create: `apps/mcp/wrangler.jsonc` with name `nudo-mcp`, a durable object binding `BRIDGE_ROOM` → class `BridgeRoom` (SQLite-backed migration `new_sqlite_classes`), `vars.ALLOWED_ORIGINS = "http://localhost:5173"`, and `observability.logs.invocation_logs: false`
- Create: `apps/mcp/src/key-hash.ts`, `src/bridge-room.ts`, `src/index.ts`
- Test: `apps/mcp/src/bridge-room.test.ts`, `src/index.test.ts`

**Interfaces:**
- Consumes: Task 1 messages and `AgentError`.
- Produces:
  - `hashKey(key: string): Promise<string>`, SHA-256 as lowercase hex.
  - `class BridgeRoom extends DurableObject` with RPC methods:
    - `dispatch(request: { tool: ToolName; args: unknown; agent: AgentIdentity; timeoutMs: number }): Promise<Result<unknown, AgentError>>`
    - `registerSession(sessionId: string, clientName: string): Promise<void>`
    - `clientName(sessionId: string): Promise<string | null>`
  - The router handles `GET /bridge/:hash` (upgrade) by forwarding to `env.BRIDGE_ROOM.get(env.BRIDGE_ROOM.idFromName(hash))`.

**Behavior to pin:**
- The upgrade is rejected with 403 when `Origin` is not in `ALLOWED_ORIGINS` (a comma-separated list).
- The first message has to be `hello`. If `hashKey(hello.key) !== hash`, the room sends `rejected/bad_key` and closes with code 4001. On a version mismatch it sends `rejected/protocol_mismatch` and closes with 4002.
- Several tabs can be connected. The **active tab** is the last one that sent `hello` or `focus`. Every tab gets `active-tab` when that changes.
- `dispatch` sends `request` only to the active tab and resolves when a `response` with the same id arrives. With no active tab, it resolves `not_connected` immediately. When the active tab's socket closes, every pending request resolves `not_connected`. When `timeoutMs` passes, it resolves `timeout`.
- Uses `ctx.acceptWebSocket` (Hibernation API) and keeps `tabId` in `serializeWebSocketAttachment`.

- [ ] **Step 1: Write failing tests** with vitest-pool-workers (`SELF.fetch` and `runInDurableObject`):
  - `rejects a bridge upgrade from a foreign origin with 403`
  - `closes with 4001 when the hello key does not hash to the room name`
  - `dispatch resolves not_connected with no tab`
  - `dispatch round-trips through the active tab`: a socket answers `response` with the same id and `ok:true,result:{n:1}`, and `dispatch` resolves `{ok:true,value:{n:1}}`.
  - `dispatch goes to the most recently focused tab`: two sockets, the second sends `focus`, and only the second receives the request.
  - `pending dispatch resolves not_connected when the tab closes` (Review Focus 1)
  - `dispatch resolves timeout after timeoutMs` (use `timeoutMs: 50`)
  - `an invalid message gets an invalid response and the socket stays open` (Review Focus 5)

**Interfaces:**

- Produces:
  - `taskTools: Pick<Record<ToolName, ToolHandler>, 'start_task' | 'set_step' | 'finish_task'>`
  - `guardWrite(agent: AgentIdentity, now: number): Result<void, AgentError>`, called by the queue before every write tool:
    - status `stopped` → `stopped_by_user`, with the message "The person stopped you. Stop and ask them before continuing."

    - `beginSnapshot(): void` keeps the graph at `start_task` (or at the implicit start).
    - `markAgentWrite<T>(apply: () => T): T` wraps every agent store action.
    - A graph subscription sets `userEditedDuringTask = true` on any graph change made outside `markAgentWrite`, ignoring undo and redo of agent entries. Detect those by comparing against the set of graphs the agent produced.
